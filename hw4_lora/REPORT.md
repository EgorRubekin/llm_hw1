# HW4: Full Fine-Tuning vs LoRA — Qwen2.5-1.5B-Instruct (Text-to-SQL)

## Задача и данные
- Модель: `Qwen/Qwen2.5-1.5B-Instruct`.
- Датасет: [`b-mc2/sql-create-context`](https://huggingface.co/datasets/b-mc2/sql-create-context) (78 577 примеров «схема `CREATE TABLE` + вопрос → SQL», собран из WikiSQL и Spider).
- Сплит: дедупликация по (question, context) → 78 576 примеров, перемешивание с seed=42. Test: первые 1000 (EM считается на первых 500), train: следующие 20 000. Одни и те же данные для всех моделей.
- Лосс считается только по токенам ответа, промпт замаскирован.

## Метрики
1. **SQL Exact Match** — совпадение сгенерированного SQL с эталоном после нормализации (регистр, пробелы, кавычки, `;`), 500 тестовых примеров, greedy-декодинг. Вспомогательные метрики: **Valid SQL** (запрос выполняется в SQLite на схеме из примера) и **test loss** (1000 примеров).
2. **MMLU** (1000 вопросов, 0-shot, выбор буквы по логитам A/B/C/D) — общие знания, по ней видно катастрофическое забывание.

## Конфиги обучения
Общие настройки: 1 эпоха (1250 шагов), batch 16, max_len 512, AdamW, cosine, warmup 3%, weight decay 0, bf16 autocast, веса в fp32, SDPA, seed 42, 1×H100 80GB. Версии: torch 2.6.0, transformers 4.56.2, peft 0.21.2.

## Выводы
- **Качество.** Full FT и LoRA дали одинаковый прирост: EM с 0.616 до 0.798, test loss в 8 раз ниже. Валидного SQL ~98% было и у Base, так что дообучение в основном научило модель соглашениям разметки, а не самому SQL. Такая адаптация низкоранговая, поэтому LoRA с 1% параметров догоняет Full FT.
- **Забывание.** У основных прогонов MMLU в пределах шума от Base. Агрессивные конфиги LoRA забывают сильнее Full FT: alpha=128 даёт −3,5 п.п., rsLoRA при r=64 даёт −9,6 п.п.
- **Параметры LoRA.** Сильнее всего на качество задачи влияет target_modules: q, v даёт EM 0.756, адаптеры только на MLP уже дают полное качество. alpha управляет компромиссом между качеством и забыванием. r в диапазоне 4–64 и dropout в пределах шума. dropout=0 экономит 2,4 ГБ памяти.
- **Затраты.** У LoRA пик памяти ниже на 15% (allocated) и на 42% (reserved), адаптер в 42 раза меньше полной модели. Выигрыша по времени на модели 1,5B нет.

Для этой задачи предпочтительнее LoRA: качество то же, памяти и места нужно меньше. Рекомендуемый конфиг все линейные слои, r=4–16, alpha 16–32, dropout=0
